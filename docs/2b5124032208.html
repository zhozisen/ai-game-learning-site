# 一页游戏设计：第一款小游戏的开工模板

先填与自己项目有关的内容。不会的字段写问题并找教师讨论，不让AI用专业词填空。复杂叙事、背包、存档、多平台和资源配表不是所有项目必需。

## 1. 玩家与玩法

- 给谁玩：___。
- 玩家通过___动作，达成___目标。
- 开始如何进入；怎样结束；如何再开始：___。
- 参照自己玩过的一个作品：___；这次只借鉴___，不复制其素材与内容。

## 2. 第一版范围

- 验证核心循环必需的功能：___（先选最少的一组）。
- 首版一个场景/关卡需要的内容：___。
- 本次明确不做：___。
- 课时与检查节点：___；超出时先删___。

## 3. 最低技术与资源

- 实际Godot版本、语言、目标平台与输入方式：___。
- 已有可以复用的练习场景/脚本：___。
- 新增的最小功能：___；尚不确定，先做小实验的点：___。
- 占位图/最终图片/音效的用途、数量、规格与许可：___。

先沿用简单节点与信号，需要额外结构时再说明原因；不要求先设计事件总线、全局管理器和全部数据表。

## 4. 功能验收：具体能不能用

填写至少三项：操作步骤___；预期变化___；边界情况___；实际结果___。可包含开始、一次核心操作、结束和重开。不用“好看、有趣”替代功能行为。

## 5. 体验假设：玩家实际会怎样

我想观察第一次玩的同学是否能___。计划让对方完成___，观察___；测试后记录事实___、原因假设___、修改/暂不修改决定___。有重开按钮不等于玩家愿意再玩，少数人的反馈不代表全部玩家。

## 6. 下一步任务

第一个可验证的小任务：___。输入资料___，允许改动范围___，检查方法___，失败如何恢复___。教师确认规模后进入第6站；以后根据实测修订，不要求开工前预测一切。
