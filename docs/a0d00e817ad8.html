04_从跟练到独立完成_实践与试玩单

完整参考原稿，按需回查。旧站号可能不同，当前任务与验收以课堂为准。

从跟练到独立完成：实践、排错与试玩单

按01开发SOP推进，需要哪项做哪项。本页为本站原创练习，不是另一套必看的课程。沿用第2站小工程，做完一个再开始下一个。

第一关：跟练后能解释

打开自己第2站工程，先不用AI，说出主场景、玩家场景、计分变量、结束条件在哪里；不清楚时让AI只解释相关几行。运行一次完整流程，保留操作记录。不会找脚本回第2站编辑器与脚本阅读。

第二关：改造一个可观察的功能

从“调整移动速度”“改变结束条件”“增加重开按钮”选一个，先写预测和操作标准，提交基线，再请AI提出小计划并修改。自己查看差异、运行正常与重复操作，核对预测。需要时可看示范，但不同时改多个功能。

第三关：独立组织一次任务

教师只给目标，例如“游戏结束后显示本局成绩，并能重新开始”。学生自己写任务卡、找相关场景/脚本、提出检查标准，再决定怎样用AI。教师不先给完整提示词或答案；卡住先提示相关概念，再给局部示范。独立指自己负责需求、操作和验收，允许查资料、使用AI和求助。

交付：任务卡、改动前后版本、操作证据，以及一个失败或边界情况。口头解释关键输入、状态和事件如何联系；不能只交AI生成的长报告。

常用功能：按当前问题选择

| 功能 | 最小操作 | 必查边界 | 不会回哪里 |
|---|---|---|---|
| 移动与输入 | 在Input Map设动作，读现有移动脚本并改一个速度 | 无输入、按住、反向 | 第2站03输入与脚本 |
| 碰撞与拾取 | 给对象配合适的碰撞形状；确认Area2D/物理体角色与层/掩码；用事件触发一次反馈 | 未接触不触发、接触正确对象才触发、重复接触不重复奖励 | 第2站官方小项目的玩家/敌人章节，先查实际版本 |
| Timer | 设置等待时间和单次/重复行为，连接timeout处理 | 未启动、到时、重开后是否多次运行 | 第2站信号与完整项目 |
| 得分与界面 | 让一个明确变量变化，更新对应Label | 初始为零、得分一次、重开归零 | 第2站脚本与信号 |
| 状态与重开 | 区分等待、进行、结束；结束后停止计分，重开清理旧对象/计时 | 快速连点、结束后输入、连续重开 | 第2站完整项目与第4站事件拆解 |
| 存档（选做） | 仅有跨会话保存需求才设计少量字段 | 首次无文件、旧记录、损坏数据如何提示 | 向教师确认所选方案与版本，不直接写入工程资源目录 |

不要只凭AI生成的API名写代码；查现有文档再在工程中运行。表格是检查范围，尚未验证学生设备上的具体实现。

一张图片进入游戏

1. 选有明确许可的一张图片，记录来源与用途，复制到工程assets/art。
2. 在文件系统中确认导入，再赋给一个Sprite2D的纹理；在检查器中观察尺寸、位置和缩放。
3. 运行，检查透明边缘、清晰度、与其他对象比例及遮挡；可见图片和碰撞形状是两回事，分别核对。
4. 对照素材规格修正，记录实际显示效果；成功后再替换其余图片。需要调整过滤或压缩时先查本机版本设置。

一个音效进入游戏

1. 记录授权，复制到assets/audio，添加AudioStreamPlayer并指定音频流。
2. 用已有的一个明确事件触发播放，先只做一次，不同时搭整套音频管理。
3. 听声音是否清晰、响度是否突变、一次事件是否重复播放；检查音量/静音在实际导出平台是否有效。
4. 需要循环BGM时另查导入与循环选项，完整听一个接缝再记录结果。

第四关：真实试玩与修复

先确定一个问题，例如“第一次玩的同学能否不听解释就开始并完成一局”。说明在测试作品，取得同意；不用收集不必要的个人信息。让同学自然操作，观察时先不代操作、不提前解释答案，结束再询问不清楚之处。

| 记录项 | 填写方式 |
|---|---|
| 环境与版本 | 哪个构建、设备/浏览器、输入方式 |
| 实际行为 | 看见什么、点了什么、哪里停住；写事实 |
| 自己的解释 | 原因假设，和玩家原话分开 |
| 分类 | 崩溃/无法推进、操作理解、体验偏好、功能建议 |
| 优先级 | 先处理阻断，再处理理解；偏好不必全部采纳 |
| 处理与复验 | 选一个问题，修改后重跑原步骤并检查邻近功能 |

示例是虚构教学案例：同学没发现重开入口 → 假设文字不清 → 调整按钮文字与位置 → 邀请再次操作并记录结果。不能把示例当作自己已经收集的反馈。没必要修改时写暂不修改的依据。

卡住的处理顺序

停止加功能 → 保存当前状态 → 确认能否重复 → 读报错的文件和行号 → 比较最近一次改动 → 做最小修复 → 原步骤复验。语法/节点引用回第2站，输入输出不清回第3站，玩法目的不清回第5站。仍解决不了，把版本、复现、预期/实际、完整报错和已尝试方法交给教师。

教师检查：能解释、能运行、能验证则通过；缺哪项就只补哪项。暂没有站内自动工程批改，不把答题和任务点当工程能力证明。
