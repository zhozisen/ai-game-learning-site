## 开场：从你最熟悉的噩梦说起

先诚实回答自己三个问题：

**问题一**：你写重要文档时，文件夹是不是长这样——

```
毕业论文.docx
毕业论文-最终版.docx
毕业论文-最终版2.docx
毕业论文-真最终版.docx
毕业论文-打死不改版.docx
毕业论文-老师又提意见了.docx
```

（笑了就说明中招了。）

**问题二**：有没有经历过——电脑硬盘坏了 / U 盘丢了 / 文件误删，几天的心血一夜归零？

**问题三**：小组作业，你把文件发到群里，另外两人各自改完再发回来，最后谁的版本是对的？合并的时候是不是想打人？

这三个噩梦，分别叫做：**版本失控、数据丢失、协作冲突**。

今天要讲的工具叫 **Git**。它一台机器解决全部三个问题：**时光机**（随时回到过去）、**保险箱**（代码永不丢失）、**协作台**（多人协作不打架）。

但先别急着往下读——先回答你心里最大的疑问："我不是专业程序员，学这个真用得上吗？"

## 第一幕：必要性——不用 Git 的人，每天在裸奔

### 场景一：单人的版本地狱

不用 Git，你管理版本的办法就是"复制粘贴改名"。文件越改越多，最后你自己都不知道哪个是最新的、改了什么、为什么改。

用 Git 之后：一个文件夹里**永远只有一份文件**，但背后藏着一份完整的"历史相册"——每一次修改都拍了一张快照，随时翻看、随时回去。文件名再也不用带"最终版"了。

### 场景二：硬盘一坏，全盘皆输

代码只在你电脑里，就是单点故障——电脑丢了、进水了、中毒了，全完。

用 Git 之后：整个项目（连着全部历史）同步一份到云端。你电脑炸了，换台电脑，一条命令，满血复活。

### 场景三：多人协作的互相覆盖

小组用 QQ 传文件的本质是：大家排队改同一份文件，后改的覆盖先改的。人一多必然出事。

用 Git 之后：每个人改各人的，Git 负责自动合并；真撞车了（改了同一行），Git 会明确告诉你"这里冲突了，你来裁决"——而不是默默覆盖、神不知鬼不觉。

**这条逻辑线**：一个又一个具体噩梦 → 世界需要一个工具一次解决它们 → 2005 年，Linux 之父 Linus Torvalds（对，写 Linux 操作系统的那位）10 天写出了 Git。它不是"众多选择之一"，它是全世界程序员的通用语言。

## 第二幕：重要性——对你，它是"门槛"不是"加分项"

可能有人想：我又不当程序员，学它干嘛？三件很现实的事：

### 1. 找工作：招聘启事上的常驻嘉宾

打开任意招聘 App，搜"程序员、测试、运维、甚至部分文员和技术支持"，职位要求十有八九写着"熟悉 Git 者优先"。在企业里不会 Git = 不会用公司的代码仓库 = 第一天就卡在门口。它像"会用微信"一样，是默认你会的东西。

### 2. 求职简历：GitHub 就是你的"作品集主页"

学生求职最大的痛点是"没工作经验"。但 GitHub 主页可以成为你的公开作品集：你做过什么项目、坚持了多久、代码写得怎么样——一张 GitHub 主页截图，胜过简历上十句"学习能力强"。**面试官看得见的东西，才叫证据。**（第 6 章每周把项目推上 GitHub，就是在攒这份证据。）

### 3. 毕业设计：保命符

毕设代码几个月的心血，用 Git 管理：电脑坏不了、版本丢不了、每次改动有记录。答辩时老师问"你这里为什么这么改"，你还能翻出历史记录讲演进过程——直接拉升印象分。

## 第三幕：核心概念——用"游戏存档"讲透 Git

### 概念 1：Git 和 GitHub，不是一个东西！（最容易混）

| | Git | GitHub |
|---|---|---|
| 是什么 | 装在你电脑上的软件 | 存放代码的网站（云平台） |
| 打比方 | 游戏的存档功能 | 云存档 + 朋友圈（晒战绩） |
| 干什么 | 记录本地文件的每次变化 | 存档备份到云上、给别人看、多人协作 |
| 再类比 | 像 Word（本地软件） | 像网盘 / 云文档（网站） |

一句话：**Git 管存档，GitHub 管云备份和炫耀。** 先有 Git（2005），后有 GitHub（2008）。

### 概念 2：仓库（Repository）——你的"存档文件夹"

用 Git 管理一个项目，就是把它变成一个仓库（程序员黑话叫 repo）。**仓库 = 项目文件夹 + 完整历史记录。** 以后你的每个项目都是一个仓库。

### 概念 3：commit（提交）——点一次"保存游戏"

这是 Git 的灵魂操作。你打游戏打到关键节点会点"存档"——万一后面打输了，读档重来。写代码一样：

```
改代码 → 觉得这波改得不错 → git commit（存档！）
继续改 → 改崩了 → 读档回到上一个存档点 ✅
```

每次 commit 记录三件事：**谁、什么时间、改了什么**（还要你写一句存档说明，叫 commit message，比如"修复了登录闪退的 bug"）。

⚠️ Git 的存档不是"另存一份文件"，而是**拍快照**——你随时能对比两张快照之间到底改了哪几行。这就是它比"复制粘贴改名"高级一万倍的地方。

### 概念 4：三个区域——超市购物模型

Git 里文件有三个状态，像逛超市：

| Git 区域 | 超市类比 | 状态 |
|---|---|---|
| 工作区 | 货架上（你正在挑挑改改） | 改动了，但还没打包 |
| 暂存区 | 购物车（挑好的先放车里） | `git add`：这批改动我打算存档 |
| 仓库 | 收银结账（购物车整体买单） | `git commit`：正式存档入库 |

为什么要购物车这一步？——**让你自己挑选哪些改动进这一次存档**。比如同时改了 3 个文件，可以只把 2 个放进这次存档，另一个下次再说。精细控制，而不是一锅端。

### 概念 5：push 和 pull——和云端同步

- **push（推送）**：本地存档上传 GitHub——购物车结完账，快递发到云仓库。电脑坏了也不怕
- **pull（拉取）**：云端最新版下载到本地——队友昨天传了新代码，你今天开工前先 pull 拿最新版

团队协作的日常节奏就八个字：**开工先 pull，下班前 push。**

### 概念 6：分支（branch）——平行世界

想做大改动，又怕改砸影响主线？开一条分支：

- **主分支（main）**：稳定版本，随时能用
- **你的分支**：一块"草稿纸"，随便折腾
- 折腾好了 → 合并（merge）回主线；折腾砸了 → 直接扔掉，主线毫发无损

这就是游戏的"二周目"：主世界安安稳稳，你在新世界随便浪。

### 概念 7：冲突（conflict）——撞车了怎么办

你和同学改了同一个文件的同一行，合并时 Git 无法自动裁决，就报告"冲突"，把两段代码都摆出来让你选。

⚠️ 这不是 bug，这是 Git 在保护你们——**它绝不会自作主张覆盖任何人的代码。冲突不是事故，是 Git 尽职尽责的报警。**

## 第四幕：AI 时代的核心用法——AI 越强，Git 越值钱

先看一个反直觉的观点。有人会说："AI 都能自动写代码了，是不是就不用学 Git 了？"

**恰恰相反。** AI 写代码有三个特点：**快、多、不听话。**

- 它 30 秒能改你 20 个文件
- 它有时一下改对，有时悄悄改崩你还看不出来
- 它没有"撤销"按钮能撤销 10 分钟前的 10 次修改

代码变化得越快、越多，你就越需要一张安全网。**Git 就是那张网。**

### 核心工作流：把 AI 当员工，把 Git 当考勤系统

记住这个节奏——**先存档，再放 AI 出去干活**：

```
① git commit   ← 存档！记下"改动前"的干净状态
② 让 AI 改代码  ← 放它出去干活
③ git diff     ← 查账：一眼看清 AI 到底改了哪些行
④ 满意 → git commit（存档，留下这个成果）
   不满意 → 一键回滚到 ①，就当 AI 没来过
```

这就是"**存档 → 干活 → 验收 → 读档**"。游戏玩家早就懂的道理，放到写代码上完全成立。

> 不会 Git 的人让 AI 改代码，就像不带保险绳走钢丝——AI 一抽风，你连它改了什么都不知道，更别说改回去。

### 三个具体的 AI × Git 玩法

**玩法一：AI 帮你写提交说明。** commit message 懒得写？把改动丢给 AI："帮我用一句话概括这次改动"——10 秒生成规范说明。

**玩法二：AI 当你的"历史侦探"。** 代码出 bug 了，把 Git 历史喂给 AI："这个功能上周还好好的，帮我看看这 5 次提交里哪次改出的问题"——AI 能帮你定位是哪次改动引入的 bug。这在以前要靠老程序员的记忆，现在人人可用。

**玩法三：GitHub 是 AI 的"外挂大脑"。** GitHub 上有上亿个开源项目，AI 编程助手就是从这里面"学"出来的。你会用 GitHub 搜索、参考别人的代码，等于站在全世界程序员的肩膀上写作业。

**一句话总结这个时代：AI 负责写得快，Git 保证错得起。会用 AI 又会用 Git 的人，正在淘汰只会其一的人。**

## 收尾：总结 + 行动

这节课一根线串到底：

**怕丢代码 → 装时光机（Git）→ 存档放云上、还能当简历（GitHub）→ 存档/购物车/结账/平行世界（核心概念）→ AI 时代的安全网（先存档再放 AI）**

### 现在就做三件小事

1. **确认 git 已装好**：知识包的安装器已经自动装过——开个黑窗口（Win+R 输 `cmd`）输 `git --version`，能出版本号就行；没有就照 `00_导读站\03_装备清单.md` 里 git 那一栏装
2. **注册一个 GitHub 账号**：按[GitHub 官方中文注册指南](https://docs.github.com/zh/account-and-profile/how-tos/account-management/creating-an-account-on-github)操作。指南里有实际注册入口；注册、邮箱验证和登录仍需本人完成。原微信文章会触发访问验证，这里直接使用官方说明。
3. **提交你的第一个 commit**：对 AI 说*"手把手带我走一遍：新建文件夹、git init、建一个 hello.txt、git add、git commit"*——五分钟，今天听懂的概念全对上号
