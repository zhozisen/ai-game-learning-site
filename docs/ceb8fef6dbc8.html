# 发布你的游戏：先在目标环境验证，再分享

前置：第6站可玩循环与试玩检查完成。首作选一个平台即可；通常可选Web或Windows，由教师结合当前工程和设备确认。沿用已有平台资料，不要求同时做手机版或商业发行。

## 发布前逐项亲测

- 主场景、输入与必需资源引用正确；无阻断流程的错误。
- 开始、核心操作、得分/反馈、结束和重开都能完成；重复重开也正常。
- 窗口、文字和操作说明在声明支持的设备上可读可用。
- 素材来源、许可、署名及平台当前AI披露要求已核对。
- 工程有可恢复版本，未将密钥、私人文件或无关数据打进包。

项目用了Autoload才检查其名称、路径和访问方式。在GDScript中启用全局访问可用注册名直接访问；不要把配置文本中是否有星号等同于所有自动加载都被启用/禁用。用编辑器设置、运行场景树和实际调用一起验证。调试日志按用途整理，不为删日志引入新错误。

## 先导出一个目标版本

记录实际Godot完整版本，安装与该版本匹配的导出模板。项目导出中添加目标预设，先解决界面提示的缺失项，再执行项目导出。不要把仅导出资源包当成独立可玩程序。

Web版保留导出的整套必需文件；按平台要求打包部署后用网址测试，不用双击本地HTML的结果代替正式验证。Windows版保留导出产生的必需文件，放到没有编辑器的目标电脑试运行。具体选项随版本和渲染器变化，遇到差异查询已有官方资料，不要求升级工程。

## 上传与说明

已有参考入口：https://itch.io

在平台创建作品页草稿，填写名称、实际操作方式、截图、版本和已知问题。Web版按平台要求上传包含入口及必需文件的包，并选择浏览器运行类型。先预览并检查，再由学生/教师确认公开与分享。不把首作设置收费作为毕业条件。

## 故障先检查哪里

| 现象 | 检查顺序 |
|---|---|
| 不能导出 | 实际版本、对应模板、目标预设提示、输出路径 |
| 编辑器正常但发布页打不开 | 文件是否齐全、入口与托管配置、浏览器报错、当前版本Web限制 |
| 图片/音频缺失 | 资源引用与大小写、导出包含范围、网络加载错误 |
| 按键或按钮无反应 | 窗口焦点、输入方式、界面遮挡、实际支持平台 |
| 声音没响 | 是否需要先进行用户交互、音量/静音、音频资源与浏览器报错 |

这些是排查方向，不保证覆盖所有环境；保留完整报错、构建版本和复现步骤找教师协助。不能为了排错盲目关闭权限限制。

## 分享后

请一位同学按说明实际玩一次，记录设备与结果。按05维护单作反馈决定，更新后复验访问链接和关键流程，再完成02毕业证据表。平台发布成功不等于所有设备都通过。
