配套讲解：概念1：节点（Node）—— 最小的积木；概念2：场景（Scene）—— 积木拼成的部件；概念4：资源（Resource）—— 数据和逻辑分家

本页只摘取当前任务指定的本站讲义章节，按页面顺序阅读；不要求读完整原稿。

概念1：节点（Node）—— 最小的积木

| 为什么 | Godot 里一切东西都是节点。不懂节点，等于不认识这个世界的"原子" |
|---|---|
| **不懂会怎样** | 你看 AI 写的代码会像看天书；Godot 编辑器里的"场景"面板对你是神秘树 |
| **是什么** | 一个只做一件事的小零件：`Sprite2D` 负责显示一张图，`AudioStreamPlayer` 负责放一段声音，`CharacterBody2D` 负责一个能移动的角色 |
| **怎么用** | 想要什么功能，就找对应节点拼上去；像搭乐高 |
| **什么时候用** | 永远。你做的每个东西都是节点的组合 |

概念2：场景（Scene）—— 积木拼成的部件

| 为什么 | 光有节点是一盘散沙，场景把节点组织成树：玩家、敌人、主菜单各是一个场景，拼成整个游戏 |
|---|---|
| **不懂会怎样** | 无法理解"为什么敌人可以做成一个文件，然后复制出 10 个"；AI 说的"实例化"你听不懂 |
| **是什么** | 一棵节点树，存成 `.tscn` 文件；场景里可以嵌套场景（把"敌人"场景放进"关卡"场景） |
| **怎么用** | 把相关节点组织成一个场景 → 保存 → 在别处像用零件一样复用它 |
| **什么时候用** | 组织任何游戏内容时 |

概念4：资源（Resource）—— 数据和逻辑分家

| 为什么 | 物品表、怪物属性、关卡配置都是"数据"。资源让数据离开代码，策划（你）改数值不用动代码 |
|---|---|
| **不懂会怎样** | 数据写死在代码里，改一个伤害数值要让 AI 重新改代码——又慢又容易崩 |
| **是什么** | Godot 的数据容器（`.tres` 文件），在编辑器右侧面板直接改，像填 Excel |
| **怎么用** | 对 AI 说："把物品做成 Resource，建 ItemData 资源类，数据用 .tres 配" |
| **什么时候用** | 任何有"表"性质的东西：物品、技能、敌人、关卡、对话 |
