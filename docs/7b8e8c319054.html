# Godot最低开发能力：从编辑器到完整小项目

目标：自己能打开工程、理解一次改动、运行验证并定位基本问题。AI可以辅助解释和实现，不能代替自己的操作。先读本站01四大概念速览，再按本页六步走；02看AI演示作为操作参考，不再只凭记住四个词或按一次运行就认为具备开发能力。

## 开始前：版本、基础与练习范围

记录本机Godot完整版本、GDScript语言和练习目录；先用Git留基线。链接优先中文官方资料，但本轮中文stable入口重定向到4.x并出现latest/unstable提示。打开后用版本选择器核对本机版本；没有对应版本时向教师确认，不能把旧版截图或API直接套用。不要求为了匹配教程升级现有工程。英文稳定版逐步入门可作对照：[Step by step](https://docs.godotengine.org/en/stable/getting_started/step_by_step/index.html)。

下面每步的练习、记录和验收是本站原创教学安排；主要技术讲解来自外链。保留同一个练习工程逐步添加内容，最后再选择一个完整小项目。不要求重复跟完多套教程，也不要求购买工具。文档打不开时保留卡点，找教师协助，不把AI猜测当官方说明。

## 1. 编辑器操作：知道东西在哪里

[官方中文：初识Godot界面](https://docs.godotengine.org/zh-cn/stable/getting_started/introduction/first_look_at_the_editor.html)

阅读项目管理器、主工作区、场景树、文件系统与检查器相关部分。亲手创建独立练习工程和2D场景，保存后运行；区分运行当前场景和整个项目，检查主场景设置。熟悉运行/停止按钮，不依赖不同键盘环境下的快捷键。

验收：关闭后重新找到并打开工程；能指出场景文件、节点属性和报错输出在哪里。截图说明自己的目录与运行画面，不只交AI生成的文件列表。

## 2. 场景与实例：从一个对象到多个对象

[官方中文：节点与场景](https://docs.godotengine.org/zh-cn/stable/getting_started/step_by_step/nodes_and_scenes.html)

[官方中文：创建实例](https://docs.godotengine.org/zh-cn/stable/getting_started/step_by_step/instancing.html)

阅读创建与保存场景、编辑器实例化部分；暂不学习MultiMesh等优化。练习：做一个简单可见对象，保存为独立场景，放入主场景两次，再改一个实例的属性。先预测效果，再观察实际运行。

验收：能区分场景文件、场景内节点和运行中的实例；说出本次改动影响哪一个对象。不要求这一步写复杂生成脚本。

## 3. 脚本阅读：先跨过最低编程台阶

[官方中文：创建第一个脚本](https://docs.godotengine.org/zh-cn/stable/getting_started/step_by_step/scripting_first_script.html)

[官方稳定版：GDScript参考](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/gdscript_basics.html)

“第一个脚本”教程默认有一定编程基础。完全零基础的同学先用下面清单逐项练习，再读旋转示例。参考手册只查当前语法，不全文通读；可切换对应版本的中文。AI每次只解释当前几行，让你先预测结果，不要一次生成整款游戏。

| 要能读懂 | 在练习中做什么 |
|---|---|
| 变量与赋值 | 找到速度变量，预测改大后会怎样，修改并运行 |
| 数字、文本、布尔值 | 区分数值计算、提示文字和是否开始的状态 |
| 函数与参数 | 找到一次调用，说明输入什么、执行什么 |
| 条件与缩进 | 判断条件成立和不成立分别会发生什么 |
| 循环 | 在小型列表上观察重复处理，不写无法停止的循环 |
| 节点引用与信号 | 指出脚本挂在哪个节点、事件交给谁处理 |
| 生命周期回调与delta | 区分进入场景的初始化与每帧更新，观察移动速度 |

验收：用自己的话解释一段短脚本，先写预测再改一个参数，核对运行结果。只会背关键字或让AI解释，不等于已会使用。暂不要求理解继承体系、复杂泛型或底层算法。

## 4. 输入与信号：操作能触发正确变化

[官方稳定版：Listening to player input](https://docs.godotengine.org/en/stable/getting_started/step_by_step/scripting_player_input.html)

[官方中文：使用信号](https://docs.godotengine.org/zh-cn/stable/getting_started/step_by_step/signals.html)

中文输入页面本轮未能读取，暂提供已核对正文的英文稳定版，可浏览器翻译；需教师协助时先记录问题。学习输入动作和Input Map，再学习按钮/计时器信号的连接与处理，按教程顺序，不同时混用多个输入方案。

练习：让方向输入控制一个对象，再让按钮改变一个明确状态或分数。检查无输入、按住输入、重复点击，以及信号断开后各发生什么。

验收：能指出输入动作、接收节点和处理函数的位置；说明事件为何只应触发一次或持续生效。本站网页信号实验作概念辅助，工程中的实际操作另行记录。

## 5. 调试：从现象找到证据

[官方中文：调试器面板](https://docs.godotengine.org/zh-cn/stable/tutorials/scripting/debug/debugger_panel.html)

先看错误、调用栈、断点与变量观察相关部分。仅在练习工程制造一个可恢复的小错误，例如改变一个节点引用，再运行观察。复制完整错误、指出文件/行号和复现动作；必要时打断点观察变量。运行结果与自己预测不符也值得调试，不只关注红色报错。

验收：交现象、错误依据、修复和复验记录；恢复原功能且不丢失之前通过的练习。AI可以帮助排查，但学生必须实际运行，不能把“AI已检查”写成测试通过。

## 6. 完整小项目：把前五步串起来

[官方中文：你的第一个2D游戏](https://docs.godotengine.org/zh-cn/stable/getting_started/first_2d_game/index.html)

具备前五步基础后，按项目设置、玩家、敌人、主场景、界面和收尾的顺序学习。官方项目是躲避敌人的小型2D游戏，不是本站接星星示例；二者任选一条做完整实践，另一条只作对照，不要求重复制作两款。选接星星时以本站02为任务说明，用官方逐步教程查需要的技术。

验收：从开始到操作、得分/存活反馈、结束与重新开始完整运行；能说明一个输入、一个信号与一个场景实例各在哪里；找同学试玩一次，并亲手修改一个可观察的小功能。保存工程、Git记录、操作检查与已知问题。导出发布放到第7站，不强迫初学时同时配置所有平台。

## 学习层级与记录

少量必学：六步里每步的一次最小练习，沿用同一个工程。按需参考：对应官方章节、01概念卡、02演示与原B站视频；无需通读全部手册。进阶选学：3D、复杂动画、性能优化与自动化，待首个完整小项目后再选。

每步记三行：我做了什么、实际看到什么、哪一点还不明白。实际工程证据需教师核对；网站现有概念题、信号模拟和积分规则不代表已经自动验收这六步，阅读链接也不会自动提升雷达分数。
