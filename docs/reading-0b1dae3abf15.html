第四关：真实试玩与修复

先确定一个问题，例如“第一次玩的同学能否不听解释就开始并完成一局”。说明在测试作品，取得同意；不用收集不必要的个人信息。让同学自然操作，观察时先不代操作、不提前解释答案，结束再询问不清楚之处。

| 记录项 | 填写方式 |
|---|---|
| 环境与版本 | 哪个构建、设备/浏览器、输入方式 |
| 实际行为 | 看见什么、点了什么、哪里停住；写事实 |
| 自己的解释 | 原因假设，和玩家原话分开 |
| 分类 | 崩溃/无法推进、操作理解、体验偏好、功能建议 |
| 优先级 | 先处理阻断，再处理理解；偏好不必全部采纳 |
| 处理与复验 | 选一个问题，修改后重跑原步骤并检查邻近功能 |

示例是虚构教学案例：同学没发现重开入口 → 假设文字不清 → 调整按钮文字与位置 → 邀请再次操作并记录结果。不能把示例当作自己已经收集的反馈。没必要修改时写暂不修改的依据。
